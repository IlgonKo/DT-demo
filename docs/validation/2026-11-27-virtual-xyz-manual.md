# 가상 X1·Y·Z 수동 운전 검증

2026-11-27 · L2 · DT Manual · Motion Server + Soft ESC

## 구성

논리 X1·Y·Z에 서버 인덱스 0·1·2를 매핑했다. 기존 TCP API와 모드별 축 지령을 사용했다. 물리 DualSense를 연결한 호스트에서 L2, 왼쪽 스틱 좌우·상하, 오른쪽 스틱 상하를 각각 Enable, X1·Y·Z PV에 사용했다.

속도 제한 시험에서만 Orchestrator의 PV 작업 범위를 X1 -8~4 mm, Y·Z -20~20 mm로 좁혔다. Motion Server의 위치 한계와 장치 파라미터는 그대로였다. 가상축의 PV 한계 계산에는 반응 시간 여유 0.25초와 위치 여유 0.25 mm를 적용했다.

## 결과

| 시험 | 관찰 결과 |
|---|---|
| HMI 다축 PP | Chrome에서 세 축을 선택해 목표 (1.000, 1.500, -1.000) mm에 도달했다. 각 축의 정지 확인 후 Ready로 복귀했다. |
| PP 중 공통 Stop | 세 축이 이동 중인 것을 확인한 뒤 브라우저의 공통 Stop을 눌렀다. 모두 B8=0이 되고 Ready로 복귀했다. |
| 물리 DualSense 다축 PV | 실제 스틱 조작으로 세 축의 순차 피드백에서 이동을 확인했다. 관찰 속도는 X1 8, Y 6, Z 9 mm/s였다. |
| X1 거리 기반 속도 제한 | X1 2.600 mm에서 입력 요청 6.274 mm/s를 4.558 mm/s 지령으로 제한했다. 이어 공통 Stop을 보내 세 축을 정지시켰다. Stop 확인까지 관찰한 X1 최대 위치는 3.669 mm로 시험 상한 4.000 mm 이내였다. |
| PV 중 공통 Stop | 물리 입력으로 PV 중 HTTP 공통 Stop을 보냈다. 실제 속도 0과 B8=0을 세 축에서 확인했으며, 새 조작 없이 이동하지 않았다. L2 해제 후 세 축 Servo Off와 제어권 반납을 확인했다. |
| 시험 범위 제거 후 회귀 | 기본 서버 범위로 로컬 서비스를 다시 실행했다. PV 이후 PP 모드 전환, 세 축 목표 도달과 공통 Stop을 재검증했다. 최종 위치 (0, 0, 0) mm, 세 축 Servo Off, 제어권 반납을 확인했다. |
| 단위 테스트 | 총 8개 통과. 대상 매핑에 기반한 전체 Stop, PP의 대상별 완료, PV 거리 제한·반대 방향 및 입력 단절 회귀를 포함한다. |

Loader, 실축 Sync 및 Omniverse 연동은 별도 M1 통합 검증 범위다.
